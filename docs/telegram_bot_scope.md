# Telegram Bot Scope (v1)

## Цель
Сделать Telegram-бота основным интерфейсом пользователя для:
- подписки на мониторинг доменов,
- получения алертов,
- подтверждения регистрации доменов,
- управления персональными правилами подбора.

## Основной сценарий пользователя
1. Пользователь пишет `/start`.
2. Бот показывает предупреждение/дисклеймер и запрашивает согласие.
3. После согласия бот регистрирует пользователя в системе.
4. Пользователь задает, какие домены искать (тематики, TLD, бюджеты, пороги score).
5. Бот присылает алерты по найденным доменам.
6. Пользователь подтверждает регистрацию кнопкой.
7. Сервис делает попытку регистрации и возвращает результат.

## Поведение команды `/start`
При первом запуске бот должен:
- показать короткий дисклеймер:
  - сервис носит информационный характер,
  - итоговая доступность домена не гарантируется,
  - пользователь принимает решение о регистрации самостоятельно;
- запросить явное подтверждение (кнопка "Принять и продолжить").

После подтверждения:
- создать/обновить профиль пользователя,
- записать факт принятия дисклеймера (timestamp + версия текста),
- открыть главное меню команд.

## Что нужно хранить

### Пользователь
- telegram_user_id
- username / first_name
- created_at / updated_at
- disclaimer_accepted_at
- disclaimer_version
- locale
- is_active

### Запросы и предпочтения
- user_id
- watch_query (текстовый запрос/тема)
- tlds (массив: .com/.io/.ai/.ru ...)
- min_score
- max_price
- status (active/paused)
- created_at / updated_at

### Подписки/уведомления
- user_id
- channel_type (telegram)
- channel_target (chat_id)
- alert_types (available/pending_delete/etc)
- quiet_hours (опционально)
- status

### История взаимодействий
- входящие команды пользователя
- действия бота (alert sent, confirm received, register attempted)
- результаты регистрации
- idempotency ключи callback-событий

## Команды бота (v1)
- `/start` — приветствие, дисклеймер, регистрация
- `/help` — список команд
- `/profile` — текущие настройки
- `/watch add <query>` — добавить правило поиска
- `/watch list` — список правил
- `/watch pause <id>` — приостановить правило
- `/watch resume <id>` — возобновить правило
- `/watch delete <id>` — удалить правило
- `/alerts on|off` — включить/выключить алерты
- `/domains now <query>` — разовый подбор доменов по запросу

## Callback-кнопки в алертах
- `register:<token>` — подтверждение регистрации
- `skip:<token>` — пропуск
- (опционально) `more:<token>` — показать подробности

## Что бот должен уметь в v1
- принимать команды и сохранять пользовательские настройки;
- отправлять персонализированные алерты;
- принимать подтверждение и запускать регистрацию;
- уведомлять о результате регистрации;
- вести журнал событий и действий пользователя.

## Что можно отложить на v2
- рекомендации на основе истории выбора;
- динамическая категоризация интересов;
- сложные сценарии budget-оптимизации;
- мультиканальные уведомления с приоритетами.

## План реализации

### Этап 1
- `/start` + дисклеймер + регистрация пользователя
- базовые таблицы users/subscriptions/user_watch_rules
- `/help`, `/profile`

### Этап 2
- `/watch add/list/pause/resume/delete`
- интеграция мониторинга с персональными правилами
- персональные алерты

### Этап 3
- подтверждение регистрации кнопкой
- попытка регистрации + результат в чат
- журнал действий/аудит

### Этап 4
- улучшения UX команд и антифлуд/rate-limit
- тонкая настройка правил и уведомлений
