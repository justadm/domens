# Telegram Template: Explainable Domain Alert

Назначение: боевой формат сообщения от бота по одному домену. Его задача - быстро объяснить, почему алерт пришел, и дать безопасные кнопки действия.

## Template

```md
## Найден домен: {domain}

**Score:** {score}/100
**Статус:** {status}
**Источник проверки:** {provider}
**Проверено:** {checked_at}

### Почему этот домен

- Совпал с watchlist: **{watch_query}**
- TLD: **.{tld}**
- Длина: **{length}**
- Сигнал: {signal_reason}
- Риск: {risk_note}

> Регистрация не гарантирована. Перед покупкой будет свежая проверка у регистратора.

Действие:
`Зарегистрировать` / `Пропустить` / `Больше таких` / `Меньше таких` / `Не повторять`
```

## Example

```md
## Найден домен: agentshield.ai

**Score:** 88/100
**Статус:** available
**Источник проверки:** Timeweb
**Проверено:** 2026-06-14 19:10 MSK

### Почему этот домен

- Совпал с watchlist: **AI security**
- TLD: **.ai**
- Длина: **11**
- Сигнал: читается как продукт для защиты AI-агентов
- Риск: перед регистрацией нужна свежая проверка доступности

> Регистрация не гарантирована. Перед покупкой будет свежая проверка у регистратора.

Действие:
`Зарегистрировать` / `Пропустить` / `Больше таких` / `Меньше таких` / `Не повторять`
```

## Button mapping

- `Зарегистрировать` -> `register:<confirmation_token>`
- `Пропустить` -> `skip:<confirmation_token>`
- `Больше таких` -> `feedback:more:<confirmation_token>`
- `Меньше таких` -> `feedback:less:<confirmation_token>`
- `Не повторять` -> `feedback:never:<confirmation_token>`

## Product rule

Алерт должен быть объяснимым сам по себе. Если нельзя заполнить `provider`, `checked_at` или `risk_note`, лучше отправить более осторожный текст или не отправлять алерт в production.
